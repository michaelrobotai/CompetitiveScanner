```bash
cp .env.example .env
```

2. Edit `.env` and fill in your values

3. Build and start:
```bash
docker-compose up -d --build
```

4. Check status:
```bash
docker-compose ps
```

5. View logs:
```bash
docker-compose logs -f
```


# Competitive Radar — Docker Setup

Stack: Node.js/Express (server-rendered Bootstrap UI), MySQL 8, Redis (job queue / scan-run progress).
Because the UI is Bootstrap served from Express `views/` + `public/`, no separate nginx/SPA container is required.

## 1. Configure environment
bash
cp .env.example .env   # or create .env from the env_template values
# edit .env and replace every "changeme_*" secret


## 2. Build & run
bash
docker compose build
docker compose up -d
docker compose ps


App: http://localhost:3000 (Login page) — health endpoint: http://localhost:3000/health

## 3. Database schema
Place your schema/seed SQL in `./init.sql`; it runs automatically on first boot of the `db` container.
If you use migrations instead:
bash
docker compose exec app npm run migrate
docker compose exec app npm run seed


## 4. Logs & troubleshooting
bash
docker compose logs -f app
docker compose logs -f db


## 5. Persistence
- `db_data` — MySQL data (competitors, signals, raw updates, runs, audit log)
- `redis_data` — queue/state for scheduled & manual scan runs
- `app_uploads`, `app_reports`, `app_logs` — uploaded files, generated PDF/CSV reports, app logs

## 6. Production notes
- Remove the public `3306:3306` and `6379:6379` port mappings so DB/cache are only reachable on `app-network`.
- Terminate TLS at an external load balancer/reverse proxy and set `APP_BASE_URL` to the public HTTPS URL.
- Set a real `SCAN_CRON` and `SCAN_RATE_LIMIT_PER_MIN` to respect source connector rate limits.
- Reset: `docker compose down -v` (destroys all data).
